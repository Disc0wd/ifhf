IFHF

A friendly command line for Flatpak. Install, remove and search apps by their ordinary name — no application IDs to memorise.

Source on GitHubDocumentationFull benchmarks

$ ifhf install spotify
Spotify
Online music streaming service

Application: com.spotify.Client
Remote:      flathub
Scope:       user

Install Spotify? [Y/n]

IFHF is a thin layer. Flatpak still downloads, verifies and deploys everything; IFHF never bypasses its signatures or permissions, runs no daemon and needs no server.

Why it is fast

Flatpak's own search re-reads about 50 MB of AppStream XML on every call. IFHF parses it once into a small local index and then answers from memory — a warm search never starts a subprocess. The first search after the index is deleted takes 577 ms; every one after that is milliseconds.

Measured with hyperfine on a 2020 laptop (i5-10310U, powersave governor), Flatpak 1.18.4; the machine is noisy (σ of 5–15 ms on fast commands). Where IFHF only wraps a Flatpak operation, it matches Flatpak or adds a little overhead for its safety checks (resolving names, “already installed”, exact partial-failure reports). Peak memory for a search: 449 MB for Flatpak, 20 MB for IFHF. Method and raw numbers are in the repository.

Two syntaxes, one behaviour

NaturalPacman-styleDoes

ifhf remove spotifyifhf -R spotifyRemove (keeps your data)
ifhf search browserifhf -Ss browserSearch every remote
ifhf info firefoxifhf -Si firefoxDetails and install status
ifhf listifhf -QInstalled apps
ifhf updates / ifhf updateifhf -Qu / ifhf -SyuList / apply updates
ifhf syncifhf -SyRefresh metadata

Built to be safe

Never guesses

Several similar matches (say, Firefox in two remotes) means you choose. In scripts it fails with a clear exit code and lists the candidates.

--yes is not blind

It never accepts a fuzzy-only match. install terminal will not quietly pick whatever app has “terminal” in its name.

Your data is kept

Remove leaves app data alone. --delete-data warns, defaults to No, and cannot be switched off in config.

No shell, validated input

Every ID and remote name is checked, and arguments reach Flatpak as separate argv entries — never through a shell.

Honest failures

Multi-app operations report exactly what succeeded and what failed. A failed metadata refresh is an error, never an empty catalogue.

Tested

Unit, integration and end-to-end tests, including the real binary against a stub Flatpak, and a real install/remove cycle in an isolated directory.

Install

git clone https://github.com/Disc0wd/ifhf.git
cd ifhf
cargo build --release
install -Dm755 target/release/ifhf ~/.local/bin/ifhf

Needs Rust and a working flatpak. Read-only commands never change your installation.
